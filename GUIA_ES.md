# Guía de la propuesta web — Adversa Technologies

## Estructura de marca aplicada

- **Empresa:** Adversa Technologies
- **Plataforma:** AdversaShield
- **Producto 1:** AdversaShield Validate
- **Producto 2:** AdversaShield Remediate
- **Paquete integrado:** AdversaShield Complete
- **Motor de inteligencia:** FINATTACK Intelligence

## Posicionamiento principal

**Categoría:** Plataforma de resiliencia adversarial para instituciones financieras.  
**Propuesta central:** *From exploitable risk to verified resilience.*

La página evita presentarse como un scanner genérico, una herramienta de parcheo o una plataforma de “IA para ciberseguridad”. El eje es demostrar exposición explotable, controlar la corrección y producir evidencia verificable de que la ruta de ataque fue cerrada.

## Decisiones de diseño

- Estética corporativa de banca y tecnología empresarial.
- Paleta azul marino, azul institucional y verde azulado.
- Uso limitado de efectos “cyber”; se priorizan claridad, control y confianza.
- Diagramas propios de rutas de ataque, evidencia, grafo financiero y ciclo de remediación.
- Mensajes distintos para CISO, AppSec, Red Team y Riesgo/Cumplimiento.
- Presentación prudente como **Private Pilot / Design Partner Program**.
- Aprobación humana antes de cualquier cambio en producción.
- No se prometen correcciones universales, cumplimiento garantizado ni operación sin intervención humana.

## Archivos principales

- `index.html`: página corporativa principal.
- `validate.html`: producto AdversaShield Validate.
- `remediate.html`: producto AdversaShield Remediate.
- `complete.html`: paquete integrado AdversaShield Complete.
- `finattack.html`: FINATTACK Intelligence.
- `company.html`: empresa, tesis, arquitectura de marca y principios.

## Para abrir la página

Puede abrirse directamente `index.html`. Para revisar todas las páginas con un servidor local:

```bash
python -m http.server 8080
```

Luego abra `http://localhost:8080`.

## Antes de publicar

1. Confirmar el dominio y la razón social definitiva.
2. Reemplazar el formulario de demostración por una integración segura con CRM.
3. Incorporar textos legales, privacidad, seguridad y política de pruebas autorizadas.
4. Sustituir los paneles conceptuales por capturas verificadas del producto cuando estén disponibles.
5. Publicar certificaciones únicamente después de obtenerlas.
6. Revisar accesibilidad, seguridad, rendimiento, SEO y cumplimiento jurídico.
